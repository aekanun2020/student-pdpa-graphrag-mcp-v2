# ทำไม repo นี้ไม่ใช้แพ็กเกจ LightRAG

repo นี้ใช้แนวคิดจาก [LightRAG](https://arxiv.org/abs/2410.05779) แต่เขียน engine เองในโฟลเดอร์ [`lightrag/`](../lightrag)
และไม่ได้ติดตั้งแพ็กเกจ LightRAG เอกสารนี้บอกเหตุผล 4 ข้อ

**ที่มาของเหตุผล:** เรียบเรียงเมื่อ 22 พ.ย. 2569 จาก 2 แหล่ง คือ README ของ
[repo ต้นฉบับ](https://github.com/aekanun2020/pdpa-graphrag-mcp) (1 ต.ค. 2569) ซึ่งบอกว่าระบบถูกออกแบบมาเพื่ออะไร
และการเทียบกับโค้ดของ [HKUDS/LightRAG](https://github.com/HKUDS/LightRAG) ที่ commit `221215e`
repo ต้นฉบับไม่ได้บันทึกเหตุผลเรื่องนี้ไว้ตอนเขียน เหตุผลในเอกสารนี้จึงเป็นการสรุปย้อนหลัง
ตารางเทียบทีละเรื่องอยู่ใน [README หัวข้อ "ต่างจาก LightRAG อย่างไร"](../README.md#ต่างจาก-lightrag-อย่างไร)

## 1. กราฟของตัวบทกฎหมายต้องตรวจสอบได้

| | LightRAG | repo นี้ |
|---|---|---|
| ผู้สร้างกราฟ | LLM สกัด entity และ relationship จากเอกสาร | กฎใน [`scripts/build_graph.py`](../scripts/build_graph.py): regex หาหัวมาตราและการอ้างมาตรา กับรายการที่กำหนดไว้ในสคริปต์ |
| ผลเมื่อรันซ้ำ | อาจต่างกันในแต่ละรอบ เพราะขึ้นกับคำตอบของ LLM | เหมือนเดิมทุกรอบ |
| การตรวจ | ต้องอ่านผลที่ LLM สกัดทีละรายการ | [`scripts/validate_graph.py`](../scripts/validate_graph.py) ตรวจจำนวนมาตราและเส้นทางไปหาบทลงโทษ |

ตัวบทกฎหมายมีโครงสร้างตายตัว ทุกมาตราขึ้นต้นด้วย "มาตรา" ตามด้วยเลข และการอ้างถึงมาตราอื่นเขียนเป็นรูปแบบเดียวกัน
กฎจึงจับได้ และคนตรวจได้ว่าเส้นแต่ละเส้นมาจากข้อความใดในตัวบท
ข้อแลกเปลี่ยนคือ การย้ายไปใช้กับกฎหมายฉบับอื่นต้องเขียนกฎและรายการใหม่

## 2. คำถามทางกฎหมายต้องเดินกราฟ 2 ทอด

กฎหมายเขียนข้อห้ามไว้ในมาตราหนึ่ง และเขียนบทลงโทษไว้ในอีกหมวด โดยอ้างกลับด้วยเลขมาตรา
ตัวอย่างหลักของ repo นี้คือคำถามเรื่องเก็บข้อมูลอ่อนไหวโดยไม่มีความยินยอม

```text
มาตรา 26 (ข้อห้าม)          จุดเริ่ม
   ↑ REFERENCES_SECTION      ทอดที่ 1
มาตรา 79 (บทกำหนดโทษ)
   ↓ PRESCRIBES_PENALTY      ทอดที่ 2
โหนดโทษอาญา
```

ลูกศรชี้ตามทิศของเส้นในกราฟ: มาตรา 79 อ้างถึงมาตรา 26 และมาตรา 79 กำหนดโทษ

| | LightRAG | repo นี้ |
|---|---|---|
| การใช้กราฟหลังค้นเจอ | อ่านต่อ 1 ขั้น คือเส้นที่ติดกับโหนดที่เจอ หรือโหนดสองปลายของเส้นที่เจอ | เดิน BFS 2 hop จาก seed ไม่เกิน 3 โหนด |
| การเลือกสิ่งที่ใส่ใน context | เรียงตามจำนวนเส้นและน้ำหนักของเส้น | เรียงตามชนิดเส้น เส้นบทลงโทษและหน้าที่มาก่อน |

การเดิน 1 ขั้นจากมาตรา 26 ไปถึงมาตรา 79 แต่ไปไม่ถึงโหนดโทษ repo นี้จึงเขียนการเดินกราฟเองใน
[`lightrag/retrieval.py`](../lightrag/retrieval.py)

## 3. Agent ต้องมี tool ที่เข้าถึงกราฟตรงๆ

MCP server ของ repo นี้มี 5 tools ในจำนวนนี้ 4 tools ไม่ได้ค้นด้วยเวกเตอร์ แต่อ่านกราฟหรือตัวบทตาม id ของมาตรา

| tool | อ่านอะไร |
|---|---|
| `get_related_sections(section_id)` | มาตราและโหนดที่เชื่อมกับมาตรานั้นในกราฟ |
| `get_penalty(section_id)` | บทลงโทษที่เชื่อมกับมาตรานั้น พร้อมเส้นทางในกราฟ |
| `get_section_text(section_id)` | ตัวบทเต็มของมาตรานั้น |
| `get_pdpa_summary()` | จำนวนโหนดและเส้นแยกตามชนิด |

tools เหล่านี้ต้องเรียกกราฟ NetworkX ในหน่วยความจำโดยตรง และต้องรู้ชนิดของโหนดกับเส้นที่ repo นี้กำหนดเอง
เช่น `PRESCRIBES_PENALTY` และ `GRANTS_EXEMPTION` การเขียน engine เองทำให้ tool ทั้ง 5 ใช้กราฟก้อนเดียวกัน

## 4. เป็นโค้ดสำหรับสอน ต้องสั้นพอให้อ่านตามได้

repo ต้นฉบับเป็นโค้ดประกอบบทความ และ repo นี้ใช้ในคอร์ส ผู้เรียนต้องเปิดอ่านโค้ดได้ทุกขั้นของการค้น

| | จำนวนบรรทัด |
|---|---|
| engine ของ repo นี้: 5 ไฟล์ใน `lightrag/` | 1,240 |
| LightRAG: 4 ไฟล์หลัก (`lightrag.py`, `operate.py`, `prompt.py`, `base.py`) ที่ commit `221215e` | 21,229 |

ตัวเลขของ LightRAG นับเฉพาะ 4 ไฟล์ ไม่รวมโค้ดของที่เก็บข้อมูลแต่ละแบบ
LightRAG ยาวกว่าเพราะรองรับที่เก็บหลายแบบ หลายโหมดการค้น และงานจริงขนาดใหญ่ ซึ่ง repo นี้ไม่ได้ทำ

## สิ่งที่ repo นี้เสียไปเพราะไม่ใช้ LightRAG

- เส้นไม่มีคีย์เวิร์ดเชิงธีมแบบที่ LightRAG ให้ LLM เขียน ผลคือ profile ของเส้นแทบไม่ถูกค้นเจอ ดู [docs/profiles.md](profiles.md)
- ไม่ได้แยกการค้นตามระดับของคีย์เวิร์ด คีย์เวิร์ด low-level และ high-level ค้น collection เดียวกัน
- รองรับกฎหมายฉบับเดียว และกราฟอยู่ในหน่วยความจำ
- ต้องดูแลโค้ดเอง ไม่ได้รับการปรับปรุงที่ LightRAG ออกใหม่

## ขอบเขตของการเทียบ

ฝั่ง LightRAG อ่านจาก paper หัวข้อ 3.1 และ 3.2 และจากโค้ดเฉพาะส่วนที่ประกาศที่เก็บกับส่วนที่ค้น
ไม่ได้รัน LightRAG ไม่ได้ทดสอบว่า LightRAG ตอบคำถามชุดเดียวกันได้ดีกว่าหรือแย่กว่า repo นี้
และโค้ดของ LightRAG เปลี่ยนได้หลังวันที่อ่าน
