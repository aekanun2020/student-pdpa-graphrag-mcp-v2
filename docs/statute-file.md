# โครงสร้างของไฟล์ตัวบท และโค้ดส่วนที่อ่านไฟล์นี้

เอกสารนี้อธิบายไฟล์ [`data/pdpa_full_text_v2.md`](../data/pdpa_full_text_v2.md) ซึ่งเป็นตัวบท พ.ร.บ.คุ้มครองข้อมูลส่วนบุคคล พ.ศ. 2562
และบอกว่าโค้ดแต่ละส่วนของ repo อ่านไฟล์นี้อย่างไร ตัวเลขและตัวอย่างทุกจุดตรวจกับไฟล์และโค้ดเมื่อ 23 พ.ย. 2569

## สรุปใน 5 บรรทัด

- ไฟล์ยาว 1,594 บรรทัด เป็น Markdown ที่ใช้หัวข้อ 4 ระดับ
- มาตราทุกมาตราขึ้นต้นด้วยบรรทัด `#### มาตรา` ตามด้วยเลขไทย มี 96 บรรทัด ไม่ซ้ำกัน
- โค้ดอ่านไฟล์นี้ 2 จุด คือ `scripts/build_graph.py` (สร้างกราฟ) และ `chunk_markdown()` ใน `lightrag/knowledge_graph.py` (สร้าง chunk)
- ทั้ง 2 จุดตัดมาตราด้วยหัวข้อ `####` เหมือนกัน แต่ทำความสะอาดข้อความและหาหมวดไม่เหมือนกัน
- ข้อความของมาตราเดียวกันจึงมี 3 รูปในระบบ ดูหัวข้อ "ข้อความของมาตรา 26 ใน 3 ที่"

## 1. แผนที่ของไฟล์

| ช่วงบรรทัด | เนื้อหา | โค้ดใช้หรือไม่ |
|---|---|---|
| 1 | หัวข้อ H1 ชื่อกฎหมาย | `chunk_markdown()` เก็บเป็น `header_1` |
| 2–38 | ข้อมูลแหล่งที่มา วันประกาศ และคำปรารภ | ไม่ใช้ ทั้ง 2 จุดเริ่มอ่านที่มาตรา 1 |
| 39–1576 | มาตรา 1 ถึง 96 คั่นด้วยหัวข้อหมวดและส่วน | ใช้ทั้งหมด |
| 1577–1579 | ผู้รับสนองพระบรมราชโองการ | `build_graph.py` ตัดออก ส่วน `chunk_markdown()` ไม่ได้ตัด |
| 1584–1594 | หมายเหตุท้ายพระราชบัญญัติ | เช่นเดียวกับแถวก่อน |

คำปรารภในบรรทัด 2–38 มีคำว่า "มาตรา ๒๖" และ "มาตรา ๓๒" ซึ่งหมายถึงมาตราของรัฐธรรมนูญ ไม่ใช่ของ พ.ร.บ. นี้
โค้ดไม่ได้อ่านช่วงนี้ จึงไม่มีเส้นอ้างอิงผิดจากคำปรารภ

## 2. หัวข้อ 4 ระดับ

| ระดับ | เขียนในไฟล์ | คืออะไร | จำนวน |
|---|---|---|---|
| H1 | `# พระราชบัญญัติ…` | ชื่อกฎหมาย | 1 |
| H2 | `## หมวด  ๑` | หมวด และบทเฉพาะกาล | 8 |
| H3 | `### ส่วนที่  ๑` | ส่วน (มีเฉพาะในหมวด 2 และหมวด 7) | 5 |
| H4 | `#### มาตรา ๒๖` | มาตรา | 96 |

สารบัญของไฟล์ตามหัวข้อ H2 และ H3:

| บรรทัด | หัวข้อ | ชื่อ (อยู่บรรทัดถัดไป) | มาตราที่อยู่ใต้หัวข้อนี้ |
|---|---|---|---|
| 39 | ไม่มีหัวข้อ H2 | (บททั่วไป) | 1–7 |
| 135 | `## หมวด  ๑` | คณะกรรมการคุ้มครองข้อมูลส่วนบุคคล | 8–18 |
| 311 | `## หมวด  ๒` | การคุ้มครองข้อมูลส่วนบุคคล | 19–29 |
| 315 | `### ส่วนที่  ๑` | บททั่วไป | 19–21 |
| 381 | `### ส่วนที่  ๒` | การเก็บรวบรวมข้อมูลส่วนบุคคล | 22–26 |
| 521 | `### ส่วนที่  ๓` | การใช้หรือเปิดเผยข้อมูลส่วนบุคคล | 27–29 |
| 584 | `## หมวด  ๓` | สิทธิของเจ้าของข้อมูลส่วนบุคคล | 30–42 |
| 878 | `## หมวด  ๔` | สำนักงานคณะกรรมการคุ้มครองข้อมูลส่วนบุคคล | 43–70 |
| 1255 | `## หมวด  ๕` | การร้องเรียน | 71–76 |
| 1351 | `## หมวด  ๖` | ความรับผิดทางแพ่ง | 77–78 |
| 1385 | `## หมวด  ๗` | บทกำหนดโทษ | 79–90 |
| 1389 | `### ส่วนที่  ๑` | โทษอาญา | 79–81 |
| 1427 | `### ส่วนที่  ๒` | โทษทางปกครอง | 82–90 |
| 1508 | `## บทเฉพาะกาล` | (ไม่มีชื่อ) | 91–96 |

ข้อที่ต้องรู้ 3 ข้อ

- **มาตรา 1–7 ไม่มีหัวข้อ H2 ครอบ** อยู่ก่อน `## หมวด  ๑` กราฟจึงมีโหนด `ch0` ที่สคริปต์ตั้งขึ้นเอง
- **ชื่อของหมวดและส่วนไม่ได้อยู่ในบรรทัดหัวข้อ** บรรทัดหัวข้อมีแค่ `## หมวด  ๑` ชื่ออยู่บรรทัดถัดไปเป็นข้อความธรรมดา
- **`### ส่วนที่  ๑` มี 2 ที่** คือในหมวด 2 และหมวด 7 ต้องดูคู่กับ H2 จึงจะรู้ว่าเป็นส่วนของหมวดใด

## 3. รูปของมาตรา 1 มาตรา

ตัวอย่างจริงรอบมาตรา 26:

```text
461  …ไปเปิดเผยเป็นครั้งแรก          ← บรรทัดสุดท้ายของมาตรา 25
462  (ว่าง)
463  #### มาตรา ๒๖                  ← หัวมาตรา 26
464  (ว่าง)
465  ห้ามมิให้เก็บรวบรวมข้อมูล…       ← เนื้อหาของมาตรา 26 เริ่ม
 …
520  …คณะกรรมการประกาศกำหนด        ← เนื้อหาของมาตรา 26 จบ
521  ### ส่วนที่  ๓                  ← หัวข้อส่วน
522  การใช้หรือเปิดเผยข้อมูลส่วนบุคคล   ← ชื่อของส่วน
525  #### มาตรา ๒๗                  ← หัวมาตรา 27
```

เลขทางซ้ายคือเลขบรรทัดในไฟล์ เครื่องหมาย … แทนข้อความที่ตัดออกเพื่อให้พอดีหน้า

| ส่วน | เริ่ม | จบ |
|---|---|---|
| หัวมาตรา | เครื่องหมาย `#` ตัวแรกของบรรทัด | เลขมาตราตัวสุดท้าย (บรรทัดเดียว) |
| เนื้อหาของมาตรา | บรรทัดถัดจากหัวมาตรา | ก่อนหัวข้อถัดไป ไม่ว่าระดับใด |

คำว่า "มาตรา ๒๖" ที่อยู่กลางประโยค เช่น "ผู้ใดฝ่าฝืนมาตรา ๒๖" ไม่ใช่หัวมาตรา เพราะไม่ได้อยู่ต้นบรรทัดหลัง `#`
ทั้งไฟล์มีคำว่า "มาตรา" ตามด้วยเลข 274 ครั้ง เป็นหัวมาตรา 96 ครั้ง

## 4. ลักษณะของข้อความที่โค้ดต้องรับมือ

| ลักษณะ | ตัวอย่างในไฟล์ | จำนวน | โค้ดรับมืออย่างไร |
|---|---|---|---|
| เลขไทย | `มาตรา ๒๖` | หัวมาตราทั้ง 96 หัว | แปลงเป็นเลขอารบิกก่อนใช้เป็นเลขมาตรา |
| ช่องว่าง 2 ช่องติดกัน | `เชื้อชาติ  เผ่าพันธุ์`, `## หมวด  ๑` | 1,390 จุด | regex ใช้ `\s+` รับช่องว่างกี่ช่องก็ได้ |
| เลขหน้าที่ค้างจาก PDF | บรรทัดที่เขียนว่า `้หนา   ๙๔` | 36 บรรทัด | `build_graph.py` ลบออก ส่วน `chunk_markdown()` ไม่ได้ลบ |
| ขึ้นบรรทัดใหม่กลางประโยค | ทุกย่อหน้า | ทั้งไฟล์ | รวมเป็นบรรทัดเดียวเมื่อเก็บเป็นข้อความของมาตรา |

สระอำแตก เช่น "จัดท า" ซึ่งโค้ดทั้ง 2 จุดมีตัวแก้ไว้ ไม่มีในไฟล์รุ่นนี้แล้ว ตัวแก้จึงไม่ได้เปลี่ยนอะไรในวันนี้

## 5. โค้ด 2 จุดที่อ่านไฟล์นี้

| | `scripts/build_graph.py` | `chunk_markdown()` ใน `lightrag/knowledge_graph.py` |
|---|---|---|
| รันเมื่อไร | ผู้ใช้รันเองเพื่อสร้างกราฟ (LAB 3) | ทุกครั้งที่ server เริ่ม |
| ผลที่ได้ | ไฟล์กราฟ ซึ่งมีโหนดมาตรา 96 โหนด และเส้นอ้างอิงระหว่างมาตรา | chunk 96 รายการ สำหรับ `pdpa_chunks` และ `get_section_text` |
| หาหัวมาตราอย่างไร | regex `^#{1,6}\s*มาตรา\s+` ตามด้วยเลข | บรรทัดที่ขึ้นต้นด้วย `#### ` |
| มาตราจบที่ไหน | ก่อนหัวข้อถัดไป หรือก่อน "ผู้รับสนองพระบรมราชโองการ" หรือก่อน "หมายเหตุ" | ก่อนหัวข้อถัดไปเท่านั้น |
| ลบเลขหน้า | ลบ | ไม่ลบ |
| หมวดและส่วนของมาตรา | จากตารางช่วงเลขมาตราที่เขียนไว้ในสคริปต์ ไม่ได้อ่านจากหัวข้อ H2 และ H3 | จากหัวข้อ H2 และ H3 ล่าสุดที่อ่านผ่านมา |
| ข้อความที่เก็บ | รวมบรรทัดหัวมาตราไว้ด้วย จึงขึ้นต้นด้วย `#### มาตรา ๒๖` | ไม่มี `####` |
| กันเลขมาตราซ้ำ | มี (เก็บหัวแรก) | ไม่มี |

การกันเลขมาตราซ้ำใน `build_graph.py` ไม่ได้ตัดอะไรออกกับไฟล์รุ่นนี้ เพราะหัวมาตรา 96 หัวไม่ซ้ำกันเลย
เป็นตัวกันพลาดสำหรับกรณีที่ไฟล์ถูกแก้แล้วมีหัวซ้ำ

`build_graph.py` ยังอ่านเนื้อหาของแต่ละมาตราอีกรอบ เพื่อหาคำว่า "มาตรา" ตามด้วยเลขที่อยู่ในเนื้อความ
ทุกเลขที่ไม่ใช่เลขของมาตรานั้นเองกลายเป็นเส้น `REFERENCES_SECTION` ได้ 124 เส้น

## 6. ข้อความของมาตรา 26 ใน 3 ที่

| ที่เก็บ | มาจาก | ขึ้นต้นว่า | ใช้ทำอะไร |
|---|---|---|---|
| ช่อง `text` ของโหนด `sec_26` ในกราฟ | `build_graph.py` | `#### มาตรา ๒๖ ห้ามมิให้เก็บรวบรวม…` | ทำ profile ของโหนด และเป็นเนื้อหาในบรรทัดผลเดินกราฟ |
| ช่อง `text` ของ chunk | `chunk_markdown()` | `[หมวด  ๒] [ส่วนที่  ๒] มาตรา ๒๖` ขึ้นบรรทัดใหม่แล้วตามด้วยเนื้อหา | แปลงเป็นเวกเตอร์ใน `pdpa_chunks` และใส่ใน context ใต้หัวข้อ "เนื้อหาต้นฉบับ PDPA" |
| ช่อง `body` ของ chunk | `chunk_markdown()` | `มาตรา ๒๖ ห้ามมิให้เก็บรวบรวม…` | คำตอบของ tool `get_section_text` |

## 7. จุดที่ไฟล์กับโค้ดไม่ตรงกัน

พบจากการตรวจเมื่อ 23 พ.ย. 2569 ยังไม่ได้แก้

1. **มาตรา 71 อยู่ผิดหมวดในกราฟ** ในไฟล์ มาตรา 71 อยู่ใต้ `## หมวด  ๕` (การร้องเรียน)
   แต่ตารางใน `build_graph.py` กำหนดหมวด 4 เป็นมาตรา 43–71 และหมวด 5 เป็นมาตรา 72–76
   กราฟจึงมีเส้น `ch4 —CONTAINS_SECTION→ sec_71` ส่วน chunk ของมาตรา 71 บอกว่าเป็นหมวด 5 ตามไฟล์
2. **chunk ของมาตรา 96 มีข้อความท้ายพระราชบัญญัติติดมา** คือชื่อผู้รับสนองพระบรมราชโองการและหมายเหตุทั้งก้อน
   ยาว 916 ตัวอักษร ส่วนข้อความของ `sec_96` ในกราฟยาว 233 ตัวอักษร `get_section_text('sec_96')` จึงคืนข้อความเกิน
3. **chunk 33 จาก 96 รายการมีเลขหน้าค้างอยู่** เช่น `้หนา ๙๕` เพราะ `chunk_markdown()` ไม่ได้ลบ
4. **chunk ของมาตรา 1–7 ขึ้นต้นด้วย `[]`** เพราะไม่มีหัวข้อ H2 ครอบ
5. **chunk บอกแค่เลขหมวด ไม่บอกชื่อหมวด** เช่น `[หมวด  ๒]` เพราะชื่อหมวดอยู่บรรทัดถัดจากหัวข้อและไม่ถูกเก็บ
6. **ข้อความของมาตราในกราฟขึ้นต้นด้วย `####`** และไปปรากฏใน profile กับผลเดินกราฟ
